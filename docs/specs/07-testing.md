# 07 Testing

Governed by [`STANDARDS.md`](../../STANDARDS.md) §9. Pyramid 70/20/10, 80% coverage minimum, 100% on validation and the error-code contract.

## The constraint that shapes the design

**No unit or integration test may require a GPU, model weights, or an external network service.**

Local containers are permitted; testcontainers Postgres is expected. The prohibition is on *external* services: HuggingFace, the RunPod API, object storage. Those make the suite slow, flaky, dependent on someone else's uptime, and dependent on credentials CI should not hold.

The GPU half is architectural. It is why `pipeline.py` exposes a lazy accessor rather than a module-level global, and why `inference.generate()` takes a pipeline parameter instead of reaching for one. A handler that cannot be imported on a laptop cannot be tested, and the fix for that is design, not tooling.

It is also what makes Phases 1, 3, and 4 runnable on a laptop, before any endpoint exists.

## Fakes, not mocks

Mock at boundaries, never internals. The boundaries are exactly the protocols: `JobRepository`, `RunPodClient`, `ImagePipeline`, `PromptGuardrail`, `ImageGuardrail`, `ObjectStore`, `Clock`.

Hand-written fakes over `unittest.mock`. A fake that records calls and returns realistic values catches contract drift; a `MagicMock` returns another `MagicMock` and asserts nothing about whether the interface was used correctly.

Recording fakes make the negative assertions possible (*"the GPU was never called"*, *"nothing was uploaded"*), and those are frequently the assertion that matters.

## Contract conformance

Package isolation means the request schema, the error codes, and the blocklist exist in both packages ([02](02-gateway-core.md#the-duplicated-contract), [04](04-guardrails.md)). These tests are the only thing preventing silent divergence, so they run in **both** suites.

| Test | Asserts |
|---|---|
| Request schema | Each package's model accepts every field in `contracts/generation-request.schema.json` with matching types, defaults, and bounds |
| Error codes | Each package's `ErrorCode` enum is exactly the set in `contracts/error-codes.json`: no extras, no omissions |
| Blocklist | Both packages load `contracts/blocklist.json` and return identical verdicts for `contracts/guardrail-corpus.json` |
| Normalisation | Both packages build their evasion-normalisation tables from `contracts/normalisation.json`: same invisibles, separators, and confusable mappings |

A drift here is the nastiest failure available: the gateway accepts a request the worker rejects, and it appears only in production.

## Unit: worker

| Area | Cases |
|---|---|
| Prompt validation | Blank, whitespace-only, 2000 characters, 2001 characters. Over-limit fails with `INVALID_PROMPT` carrying the actual length and the cap |
| Dimension snapping | Parametrized: 255, 256, 1000, 1023, 1024, 1536, 1537. Effective values appear on the result |
| Parameter ranges | Steps and guidance at, inside, and outside their bounds |
| Handler success | Fake `ImagePipeline`; asserts echoed seed, effective dimensions, `model_version`, and `image_base64` populated with decodable PNG bytes |
| Handler OOM | Fake raising `torch.cuda.OutOfMemoryError`; asserts `refresh_worker: True` and the `OOM` code |
| Handler failure | Fake raising a generic exception; asserts `INFERENCE_FAILED` and that internal detail is **not** in the response |
| Seed | Absent seed is randomised and echoed; supplied seed reaches the pipeline unchanged |
| Progress | `callback_on_step_end` fires per step; `progress_update` is throttled to every `PROGRESS_STRIDE_PCT`: first step and final step always report, and the call count is bounded by ~100/stride regardless of steps |
| Guardrail: prompt | Normalisation defeats casing, spacing, punctuation, zero-width characters, combining marks, confusable substitution: one parametrized case per evasion, using synthetic tokens |
| Guardrail: false positives | Word-boundary matching does not fire on blocked substrings inside innocent words. This is the failure that makes naive blocklists unusable |
| Guardrail: chain | Returns the most severe verdict across members |
| Guardrail: failure policy | A raising guardrail stops the request (fail closed) and is reported as `INFERENCE_FAILED`, never `PROMPT_BLOCKED`/`IMAGE_BLOCKED`. No timeout case: nothing in the built chain can hang ([04](04-guardrails.md#failure-policy)) |
| Guardrail: ordering | A blocked prompt never reaches the pipeline; the pipeline fake records zero calls |
| Guardrail: image | Invoked with the generated bytes; **a blocked image is never uploaded**: the store fake records zero writes |
| Weights resolution | No `WEIGHTS_PATH` and no cache fails fast at startup, naming all three mechanisms; a cache snapshot resolves via `refs/main`, or as the sole snapshot; several snapshots with no ref refuses to start rather than guess; the revision is discovered from the snapshot name or the baked `MANIFEST.json` |

## Unit: gateway

| Area | Cases |
|---|---|
| `JobService.submit` | Guardrail runs before the insert; a blocked prompt is persisted as `BLOCKED` and never submitted; the RunPod fake records zero submissions |
| `JobService.get` | Known id returns the job; unknown returns `None` |
| `JobService.reconcile` | Advances non-terminal jobs; **an upstream exception leaves the job untouched** rather than failing it; a terminal job is never moved backwards; one job raising does not abort the batch |
| Status mapping | Every RunPod status maps to exactly one domain status; an unknown status raises rather than defaulting |
| Progress | Stored on the job; never alters `status`; ignored on a terminal job |
| Timeout | A job past `created_at + 600s` becomes `TIMED_OUT` with `JOB_TIMEOUT`; one a second inside the deadline does not |
| Auth | Valid, invalid, missing, and malformed headers; `api_key_id` lands in `RequestContext`; comparison uses `hmac.compare_digest` |
| Queue pressure | Over threshold returns `QUEUE_SATURATED` with `Retry-After`; under threshold passes; **a stale or missing cached health value allows the request through**: fails open, unlike guardrails |
| Circuit breaker | Opens after N consecutive failures, fails fast while open, half-opens, closes on a successful probe |
| Retry | Retries 5xx and timeouts, does **not** retry 4xx, respects the attempt cap, applies jitter |
| Clock | Timestamps come from the injected clock, asserted against a frozen value |

## Integration

| Area | Cases |
|---|---|
| Repository | **Not built as specified.** Persistence is `InMemoryJobRepository`, so there is no Postgres and no testcontainer; its CRUD, transitions, `claim_unresolved` ordering and limit are covered as unit tests instead. The `SKIP LOCKED` concurrency case arrives with the Postgres adapter ([02](02-gateway-core.md)) |
| **Idempotency race** | **Genuinely concurrent inserts with the same key.** One wins, the other returns the existing job. A sequential test passes against the broken implementation and is therefore worthless |
| Idempotency conflict | Same key with a different body returns `409 IDEMPOTENCY_CONFLICT` |
| Idempotency scoping | Two different `api_key_id`s using the same key get two separate jobs. Neither can see the other's; this is a data-leak test, not a convenience test |
| RunPod adapter | Mocked transport: response parsing, status mapping, retry, breaker, timeouts, endpoint-health parsing |
| API | FastAPI `TestClient` with fakes for RunPod and storage. Submit, poll, 404, 401, 409, 429, error envelope shape, `X-Correlation-ID` echoed |
| Cancel | Delegates to RunPod's cancel and records `CANCELLED`; a terminal job is returned unchanged with no upstream call, so a completed result is never discarded; unknown id is 404 |
| Health | `/health` responds without a credential; `/health/detailed` requires one and reports RunPod and reconciler state (no database component while persistence is in-memory); a dead reconciler surfaces as stale `last_tick_s`, and a queue reading older than `HEALTH_MAX_AGE_S` reads as unknown rather than shedding forever |
| Reconciler loop | Ticks on schedule, backs off when idle, and shuts down cleanly on cancellation without leaving a write half-applied |

## The SDK's own harness

The pytest suite is the CI gate. RunPod's SDK harness is the **image smoke test**: the documented way to prove the image works before an endpoint exists, and the layer a RunPod reviewer will look for. No Pod is involved; it runs wherever the image was built, and the GPU-touching cases need a GPU host.

| Tool | What it proves | When |
|---|---|---|
| `test_input.json` (committed) | `python -m worker.handler` runs exactly one job through the real handler, pipeline and GPU, no queue involved | On any GPU host holding the image, before push |
| `--test_input '{"input": ...}'` | Same, with an inline payload; used for the OOM and blocked-prompt smoke cases | On a GPU host |
| `--rp_serve_api` | FastAPI simulator of the endpoint surface on `localhost:8000`; `POST /runsync` exercises submit-through-response without deploying | Anywhere for the surface itself; an actual `/runsync` still loads the pipeline, so a GPU host |

This slots between "image pushed" and "endpoint created" in the runbook and separates *the image is broken* from *the endpoint is misconfigured* while both are still cheap to tell apart. Not part of `make check`: everything here needs the GPU image.

## E2E

`@pytest.mark.gpu`, deselected by default, run by hand against a live endpoint. Blocked until Phase 2b.

| Case | Purpose |
|---|---|
| Prompt → image | The graded demonstration |
| `/runsync` one-liner | The single-command demo in [01](01-worker.md#the-demonstration-is-one-runsync-call) returns a decodable image against a warm worker |
| Same seed twice | Reproducibility |
| **Weight variants, identical weights** | **`sha256` of the weight files matches across every deployed variant (baked, volume, cached)**, reported by a debug field on the health response. Output pixels are *not* compared: two invocations land on different physical GPUs, and bf16 kernel and cuDNN algorithm selection are not bit-reproducible across hosts, so an image diff would fail for reasons unrelated to weights. Hashing is exact, free, and needs no generation |
| Progress mid-generation | Polling during a job returns increasing `percent` |
| Idempotency replay | Same key returns the same job; RunPod shows one execution, not two |
| Blocked prompt | Guardrail path through the real stack, ending in `BLOCKED` |
| Cold start timing | Feeds `BENCHMARKS.md` |

## Doctests

Scoped per package, so collection never imports GPU-touching modules:

```
uv run pytest --doctest-modules src/gateway/core src/gateway/api/schemas.py
uv run pytest --doctest-modules src/worker/schemas.py src/worker/guardrails.py
```

Per [`STANDARDS.md`](../../STANDARDS.md) §10, `Example` blocks are required only where genuinely runnable and forbidden where they cannot execute, so everything written as `>>>` is verified rather than decorative.

## What is not tested

- **Image quality.** No automated check. Visual inspection during Phase 2b, with the step grid in [09](09-benchmarks.md).
- **Guardrail classification accuracy.** The blocklist is tested for correct mechanics, not for whether the list is right: a content question, not an engineering one.
- **Load and concurrency behaviour.** No load test; the queue threshold and concurrency limits are reasoned, not measured. See [08](08-production-readiness.md).
- **The RunPod platform itself.** Fakes assert we handle its documented contract. If the real API diverges, only E2E catches it.
